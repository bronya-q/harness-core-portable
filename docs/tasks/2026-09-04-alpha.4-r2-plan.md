# R2 阶段规划

> R1 证明“本地能跑、能力都在”；R2 要证明“外面的人真的能装、真的能用、真的觉得对，并且有外部证据”。

## 核心目标

```text
从“本地 R1 原型” → “外部可验证、可发布、可持续维护的 R2 基线”
```

## 当前进度（2026-09-04）

- 已落地：`mcp-verify`、`project-check`、`release-checklist`、`user-test checklist/template/simulate`、`secret-scan`、`migration apply/apply-script`、`usage audit`、letter thread、knowledge 索引检索、角色分工/信件/运行上下文可视化、scope 规范化覆盖多入口。
- CI 已接入：`secret-scan` / `mcp-verify` / `release-checklist`。
- 仍未做：真实宿主、Registry/PyPI、真人首测、真实双标注/效度、完整 OS 沙箱、全入口 runtime 热挂载。

## 可执行工具链

```text
release-checklist    R2 DoD 勾选
project-check        聚合体检
mcp-verify           MCP 复现验证
user-test checklist/template/simulate   首测管线
secret-scan          密钥扫描
migration apply/apply-script   迁移
```

## P0：外部真实验证

| 事项 | 验收 |
|---|---|
| MCP Inspector 固定进 CI / 干净环境跑 `mcp-verify` | `project-check` 全绿 |
| Claude Code / Codex / Copilot 真实宿主各跑一次 | 每个宿主回填 1 条记录 |
| Official MCP Registry 提交 | 有 listing id / 审核记录 |
| TestPyPI + PyPI 发布 | `pip install harness-core-portable` 成功 |
| alpha.4 / alpha.5 tag + Release | Release 页面 + ZIP 回读 + Deployment record |

## P0：首次用户真实测试

- 找 5 个没接触过项目的人
- 使用 `user-test checklist` 跑 `demo / dashboard / memory / correct / forget / restore`
- 结果填回 `results-template.md`
- 重点记录：放弃点、误判 gate FAIL、activate 误解、静态 HTML 安全误解
- 验收：至少 1 条真人记录，并把关键误解放进 README 修改

## P1：生产化运行时

| 事项 | R1 现状 | R2 要做 |
|---|---|---|
| 全入口 runtime 热挂载 | `runtime-context.json`，但只被 roleplay 消费 | MCP / workspace / memory list 也读同一 context |
| scope 规范化 | 已覆盖 memory/event/letter/inspect/notebook/story | 覆盖全部 CLI 入口 + 单元级断言 |
| knowledge 委派 | `suggest` 已返回分工/信件 | 真正“当前角色无权 → 转交负责角色”的自动路由 |
| 完整文件系统沙箱 | dry-run + `--isolate` 临时副本 | OS 级隔离（容器/WSL/受限用户），禁写/禁网/禁外部 |
| adapter gate | MCP stdio + HTTP | 所有宿主前端 + 未授权即拒绝的强制默认 |

## P1：测量学信效度

- 用真实双标注数据跑 `measure reliability`
- 报告 Cohen’s κ / Krippendorff’s α
- 至少给 3 个核心构念（召回命中、跨 scope 泄漏、用户满足度）建立信效度
- 不把“工具能算”写成“效度已建立”

## P1：文档/边界一致性

- `AGENT_COMPATIBILITY` 升级到 R2 等级（README + JSON + `ecosystem status` 三方一致）
- `HYBRID / ENGINEERING / SKILL` 再扫一遍，确保无私人示例名
- `remaining-gaps.md` 从“清单”变成“可勾选 release checklist”

## P2：发布工程

- PEP 440 版本策略固化（`0.1.0a4` 等）
- `migration` 从“补列”升级到“版本化 schema migration 目录”
- `deprecation window` 写入文档
- 新增 `release checklist`，跑 `project-check` + 公共边界 + `secret-scan` + `migration check` + `mcp-verify`

## R2 Definition of Done

```text
[ ] project-check 在干净环境全绿
[ ] mcp-verify 通过并在 CI 固定
[ ] 真实宿主至少一个回填结果
[ ] 首次用户真人至少一条记录
[ ] Registry listing / PyPI 至少一个可回读
[ ] alpha.4 或 alpha.5 Release 页面 + ZIP 回读
[ ] 全域 scope 规范化测试
[ ] knowledge 自动委派路由可运行
[ ] 文件系统沙箱达到“临时隔离 + 禁写/禁网”级别
[ ] 至少 3 个构念有双标注信度数字
```
