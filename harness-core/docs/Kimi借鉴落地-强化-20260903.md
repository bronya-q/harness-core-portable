# Kimi 借鉴落地：强化本系统（2026-09-03）

> 重点：学习借鉴并强化 harness，不纠结仓库。

---

## 1. Kimi 最核心的启发

```text
长上下文不是目的，持久记忆与个性化才是。
多 agent 不应挤在一个大窗口里，而应“各自 notebook + 共享 story core”。
```

## 2. 已落地强化

### notebook.py — 每个 agent/role 一个持久笔记本
```bash
python harness.py notebook note --scope 'game:demo' --text '故事核心：…' --kind manual
python harness.py notebook list --scope 'game:demo'
python harness.py notebook versions --scope 'game:demo'
```
- 自动笔记（auto）+ 用户 memo（manual）
- 带版本链（version/prev_id）

### story_core.py — 共享世界/任务核心
```bash
python harness.py story set --namespace 'story:game-demo' --content '…'
python harness.py story get --namespace 'story:game-demo'
```
- 多角色/多任务共同引用，避免上下文爆炸。

## 3. 对下游任务的意义

| 任务 | 用法 |
|---|---|
| 游戏开发 | 每个角色一个 notebook，共享 story core 维护世界观 |
| 论文/报告 | 每个研究主题一个 notebook，共享 core 记录研究主线 |
| 公司网页/产品 | 一个工程 notebook + core 记录需求/偏好 |
| 文书工作 | notebook 记录关键条款，core 记录主题框架 |
| 角色扮演 | 每个角色 notebook 记录经历，core 记录当前世界状态 |

## 4. 状态（按证据分级）

### 已实现（live 可运行）
- notebook note/list/versions/summary/quote/timeline/restore
- story set/get/history/diff/restore
- roleplay collab block 注入（`--story-namespace` / `--notebook-auto`）
- notebook auto-note（会话后写 prompt 前 80 字，要求 response 成功且无 error）
- collaboration runtime policy + 字符预算（runtime-policy.json `collaboration_context`）

### 部分实现（明确边界）
- `notebook summary` 是**最近 N 条条目拼接摘要（bounded recent-note digest）**，不是语义摘要；
- `--notebook-auto` 记录的是**用户 prompt 前 80 字的会话提示条目**，不是 AI 自动提炼记忆；
- roleplay collab 注入有 telemetry（collab_telemetry），且异常不静默成“正常空结果”。

### 未实现 / 需持续跟踪
- portable 仓库的完整同步与端到端测试
- 更完整语义摘要 / 冲突消解 / 重要性排序
- 跨机器一致性与并发写入测试

---

> 结论：借鉴 Kimi 的“notebook + story core”不是加文档，而是给系统增加**跨角色/跨任务持久协作层**。
