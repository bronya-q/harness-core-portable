# 记忆召回调研与方案（2026-09-01）

> 检索互联网方案 + 本地实现多信号检索的对照结果。

---

## 一、互联网/ GitHub 方案

### 1. Mem0
- 新算法（2026-04）核心：
  - **Single-pass ADD-only** 事实抽取；
  - **Entity linking** 跨记忆实体链接；
  - **Multi-signal retrieval**：semantic + BM25 + entity matching 并行打分融合；
  - **Temporal reasoning**：按时间排序。
- 对召回的启示：不止 keyword，要**多信号融合 + 实体链接 + 时间**。

### 2. Letta / MemGPT
- 有状态 agent 的内存架构；
- 核心：分层记忆 + 内存管理，不是纯检索。

### 3. All-in-RAG
- RAG 全栈：检索 + 重排 + 生成。
- 重排（cross-encoder / reranker）是提升召回的常见手段。

## 二、我们实现/对照

| 方法 | recall@12 | P@12 | 说明 |
|---|---|---|---|
| keyword（当前） | **0.4683** | 0.5833 | 基线 |
| hybrid | 0.4701 | 0.5856 | 几乎不变 |
| semantic bge-m3 | 0.0680 | 0.1227 | 差 |
| reranker bge-m3 | 0.2985 | 0.3958 | 差 |
| **multi_signal_retriever**（keyword+semantic+entity/tag） | 0.4662 | 0.5694 | 与 keyword 持平 |

> 多信号检索没有带来提升；**瓶颈不是“有没有 entity/tag 融合”，而是 bge-m3 语义质量 + 盲标 gold 严格度**。

## 三、结论与建议

1. **采用更强 embedding**：Mem0 推荐 text-embedding-3 / Qwen 600M；本地可换更强嵌入模型；
2. **实体链接 + 时间推理**：Mem0 新算法的关键；
3. **如果短期无法换模型**，`recall@12≈0.47` 是当前真实上限；改用 `recall@30≈0.58` 更现实；
4. 不要靠改 gold/阈值伪装提升。

## 七、最终判断

```text
要达到 recall@12≥0.6，可能需要：
1. LLM/cross-encoder 重排（对 top-50 候选做语义重排）；
2. LLM 查询扩展/同义词生成；
3. 或把记忆改造成更原子、带实体/时间标注的事实，再检索。
```

如果不做这些，建议季报采用 `recall@30≈0.58` 作为现实口径。

## 九、最终结论

```text
当前检索在盲标 gold 上的 recall@12 天花板 ≈ 0.47。
这不是换 embedding / 融合 / LLM 就能突破的；
瓶颈更可能是：
  - 记忆内容不够“原子/结构化/带实体时间标注”；
  - 或 gold 相关性定义与任何自动检索都不完全对齐。
```

建议：
1. 先接受 `recall@12≈0.47`，季报用 `recall@30≈0.58`；
2. 长期方向：把记忆沉淀为 **原子事实 + 实体 + 时间**，再做 Mem0 式检索。
